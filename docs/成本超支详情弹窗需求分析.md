# 成本超支详情弹窗 — 需求分析

> 版本：v1（待确认）
> 日期：2026-09-10
> 关联模块：E 区域「成本管控」（`CostTable.vue` / `costData.js`）

---

## 一、需求背景与目标

### 现状
E 区域成本明细表当前只展示**汇总结果**：某项目某科目「立项成本 / 实际支出 / 差额」，超支行整行标红。

### 痛点
管理者看到「项目分包费 超支 +20 万」后，**无法知道钱花在哪**——是哪几家供应商、哪几份合同、各自多少钱，无法定位超支主因，也无法据此发起整改。

### 目标
在明细表每行提供入口，点开可下钻到**「项目 → 成本科目 → 支出合同」**三级明细，实现超支可追溯。

---

## 二、现状盘点（已核对）

### 2.1 数据链路

```
支出合同事项.xlsx（2021 行，首行为标题需跳过）
  │  cleanContractData()  ← 目前只保留 3 个字段
  ↓  { projectCode, contractType, amount }
buildContractCostMap()      ← 按项目编号 + 分类聚合为金额
  ↓  Map<项目编号, { [分类key]: 金额 }>
buildCostRow()              ← categories 只有 budget/actual/diff/over
  ↓
CostTable.vue               ← 只渲染汇总数字，明细被丢弃
```

**关键结论：合同明细在第 2 步就被聚合掉了，必须在数据层保留明细才能支撑下钻。**

### 2.2 支出合同表可用字段（已核对真实列名）

| 字段用途 | Excel 列名 | 备注 |
|---|---|---|
| 关联键 | `项目编号` | 与台账项目编号一致，非空 1040 个 |
| 分类键 | `支出合同类型` | 项目分包 269 / 软硬件 1214 / 项目管理 518 / 其他 5 |
| **计入成本金额** | `事项金额(元)` | 当前口径使用的金额 |
| 合同编号 | `数研院合同编号` | |
| 合同名称 | `合同名称` | |
| 签订时间 | `合同签订时间` | YYYY-MM-DD |
| 事项名称 | `事项名称` | |
| 合同总额 | `合同总金额元` | 与事项金额不同，可作参考 |
| 供应商 | `乙方合同签约单位` | |
| 承办人 | `承办人` | |
| 采购类型 | `采购类型` | |
| 合同状态 | `合同状态` | |
| 付款情况 | `合同付款已支付` / `合同付款待支付` | |

> 数据量参考：单个项目最多 7 条合同；全表 2021 行。

## 三、需求细化

### 3.1 交互入口

- 位置：成本明细表（`CostTable.vue`）行尾新增**「详情」按钮**列。
- 建议：**所有行都显示按钮**（未超支行也能查看成本构成），超支行的按钮使用强调色。
  - 理由：未超支项目同样有"钱花在哪"的查询诉求，且实现成本一致；「仅超支」筛选已能满足"只看超支行"的场景。
- 点击后打开详情弹窗，**不改变当前筛选与分页状态**。

### 3.2 弹窗信息架构（三级）

```
┌─ 项目名称 + 项目编号                              [×] ┐
├─ 项目信息条 ─────────────────────────────────────┤
│  项目经理 / 业务部所 / 项目类型 / 计划终验 / 实际终验 │
├─ 成本科目概览 ───────────────────────────────────┤
│  [项目分包费]  [软硬件采购]        ← 分类切换（超支标红）│
│   立项 100万 · 实际 120万 · 差额 +20万 ⚠超支          │
├─ 该科目支出合同明细 ─────────────────────────────┤
│  合同编号 | 合同名称 | 签订时间 | 事项名称 |          │
│  事项金额 | 合同总额 | 乙方 | 承办人 | 采购类型       │
│  ...（按事项金额倒序）                              │
└──────────────────────────────────────────────┘
```

- **分类切换**：点击科目卡片切换下方合同列表；存在超支科目时默认选中**超支金额最大**的科目，否则选第一个。
- **金额倒序**：合同按 `事项金额(元)` 从大到小排列，便于第一眼看到主要支出。

### 3.3 空值与异常

| 场景 | 表现 |
|---|---|
| 该科目无任何支出合同（实际支出 0） | 「该成本科目暂无支出合同记录」 |
| 合同字段为空（如无合同状态） | 显示 `-` |
| 项目所有科目都无合同 | 弹窗仍可打开，概览区正常显示立项成本 |
| 合同条数过多 | 弹窗内表格区域独立滚动，表头吸顶 |

### 3.4 交互细节

- 关闭方式：右上角 `×` / 点击遮罩 / `Esc` 键。
- 打开时锁定页面滚动，关闭后恢复。
- 弹窗宽度约 1100px，内容超高时整体滚动。

## 四、数据层改造

### 4.1 扩展清洗字段（`cleanContractData`）

在现有 3 个字段基础上补齐明细字段（**向后兼容**，`buildContractCostMap` 只用其中 3 个）：

```js
{
  id,              // 行唯一键（合同ID + 事项ID，缺失时用行号兜底）
  projectCode,     // 项目编号
  contractType,    // 支出合同类型
  amount,          // 事项金额(元)      ← 计入成本
  contractNo,      // 数研院合同编号
  contractName,    // 合同名称
  signDate,        // 合同签订时间
  itemName,        // 事项名称
  contractAmount,  // 合同总金额元
  supplier,        // 乙方合同签约单位
  handler,         // 承办人
  purchaseType,    // 采购类型
  contractStatus,  // 合同状态
}
```

### 4.2 保留明细索引（`costData.js`）

```
新增 buildContractIndex(contracts) → { amountMap, detailMap }
     amountMap: Map<项目编号, { [分类key]: 金额 }>      ← 现有逻辑
     detailMap: Map<项目编号, { [分类key]: 合同数组 }>   ← 新增，支撑下钻
保留 buildContractCostMap(contracts) = buildContractIndex().amountMap   ← 兼容现有测试
```

`buildCostRow` 中每个分类增加 `contracts: []` 字段（按金额倒序）。

### 4.3 导出增强（可选）

`下载Excel` 增加第二个 sheet「合同明细」，导出当前筛选范围内所有超支科目对应的合同行。
> 默认：**本期不做**，保持导出格式不变，避免影响现有使用习惯。

## 六、设计决策（已确认 2026-09-10）

1. **「详情」按钮显示范围**：✅ 全部行都显示（超支行按钮使用红色强调样式）
2. **弹窗形态**：✅ 居中弹窗（`Teleport` + 遮罩，宽 1100px，最大高 88vh）
3. **合同列表组织**：✅ 按科目切换（超支科目默认选中，取超支金额最大者）

---

## 七、不改动的部分（明确边界）

- 不修改成本计算口径（仍以 `事项金额(元)` 为准，仅统计 `项目分包` / `软硬件`）。
- 不修改台账上传与项目明细表逻辑。
- 不引入新的第三方依赖（弹窗用原生 `div` + `Teleport` 实现）。
